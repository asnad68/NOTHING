VERQIVIA security boundary

The public prototype is designed to fail closed around wallet access. A visible identity record is not permission to move funds.

Public prototype status

Wallet connection: DISABLED

The public GitHub Pages deployment does not request wallet access or transactions by default. This avoids asking users to bypass a browser-wallet security warning while the domain is under manual review.

When wallet enrollment is enabled

The browser uses the standard injected wallet provider interface and does not request a seed phrase or private key.

The current payment path uses explicit account and chain discovery followed by one server-issued native-asset transaction. The browser does not use token approvals or arbitrary message signatures for enrollment.

The server, not the browser, is responsible for invoice creation, payment matching, receipt verification, finality checks and identity creation.

What cryptographic proof means

A valid VERQIVIA proof can bind a published record to a signing key. It does not by itself prove that an underlying business claim is true.

Reporting a security issue

Please report security problems through the repository's Security page. Do not publish private keys, seed phrases, credentials or other secrets in an issue.
